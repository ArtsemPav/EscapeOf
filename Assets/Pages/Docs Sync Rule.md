Правило синхронизации документации для всех, кто работает с Bezi в этом воркспейсе.

## Каноничные источники документации

В проекте два зеркала документации:

1. `/Pages` — страницы Bezi (Private)
2. `/EscapeOf/Assets/Pages` — копии внутри Unity-проекта (видны в редакторе Unity, забираются из воркспейса)

Файлы носят одинаковые имена (`Horror System.md` → `/EscapeOf/Assets/Pages/Horror System.md`).

## Правило

Любое создание, изменение или удаление страницы документации выполняется **в обоих местах сразу** в одной задаче:

- поправил страницу в `/Pages` — внеси ту же правку в `/EscapeOf/Assets/Pages/<то же имя>.md`;
- создал страницу в `/Pages` — создай её копию в `/EscapeOf/Assets/Pages`;
- удалил страницу — удали зеркало.

Синхронны обе стороны: если правка сделана в `/EscapeOf/Assets/Pages` (например, из Unity), перенеси её и в `/Pages`.

## Рабочий процесс команды

Коллега ведёт и актуализирует документацию в `/EscapeOf/Assets/Pages` (в Unity). При начале работы над задачей Bezi сначала сверяет `/Pages` с `/EscapeOf/Assets/Pages` и подтягивает оттуда свежие изменения в страницы Bezi, прежде чем что-то менять. Внутри одной задачи оба зеркала снова синхронизируются по правилу выше.

## Исключения

- Страницы, существующие только в одном месте на момент чтения (`/Pages/Private`: Progress Logger System, Wake-Up Intro System, Endings and Credits Architecture, PhotoCraft MCP, Pressure Puzzle System и др.), зеркалировать при правках **не нужно**, пока они не появились во втором месте.
- Технические страницы `👋 Welcome to Pages!.md` синхронизации не требуют.

## Чеклист перед завершением задачи с правкой документации

1. Список изменённых страниц собран.
2. Для каждой есть парная правка во втором зеркале (или она в списке исключений).
3. `grep` по ключевым терминам правки не находит устаревших упоминаний ни в `/Pages`, ни в `/EscapeOf/Assets/Pages`.
